## LUT source provenance and dependency closure (follow-up, audit only)

Read-only inspection of V1 `imaging/lut/Lut3D.kt:1-46` and `imaging/lut/CubeLutParser.kt:1-60`: both begin with a package declaration; **neither file has a license header or attribution comment**. An absence of a header does not establish ownership or commercial redistribution rights. A glob at V1 repository top level found `photobooth/LICENSE` and `photobooth/LICENSE_NOTICE` under a nested subtree, but no root-level LICENSE/COPYING/NOTICE; the nested files were not interpreted as licenses for these Kotlin sources. **No commercial redistribution claim** may be made until provenance/rights are independently verified. No bundled `.cube` file is needed or authorized for copying; create synthetic in-memory LUT fixtures for tests.

The two-file algorithm's source dependency closure is exactly `CubeLutParser` → `Lut3D`; both rely only on Kotlin standard library (`ArrayList`, text/float parsing, math) and Java/JDK APIs (`Files`, `Path`, `BufferedImage`). Neither imports a V1 service, model, Beauty class, Canon API, printer API or third-party library. `CubeLutParser.parse(Path)` currently reads all text without byte limits; a bounded V2 asset service must reject oversized files **before** calling it, not retune parsing/interpolation. The parser accepts sizes 2..65, 3 channels, complete cubic row counts, finite numbers, valid ordered domain, duplicate/late directive rejection and 1D rejection (`CubeLutParser.kt:17-59`). `Lut3D.apply` computes trilinear RGB interpolation with alpha preservation and clamped 0..1 intensity (`Lut3D.kt:14-45`). Neither proves file-copy provenance, effect config persistence or runtime application; those are separate concerns.

For a byte-exact source copy, retain each original file byte-for-byte in a V2 `.../imaging/lut/` path **with its original package** (Kotlin can compile a package independent of its directory); no imports in these two files need changing. If package migration is mandated, change only line 1 of each file and compare remaining source bytes/lines. Offline comparison approach after authorized V2-only implementation: use read-only access to these **two named V1 source files** through `read` (or a narrowly approved explicit-path read-only hash command; never a V1 working directory), calculate SHA-256 of original bytes and copied V2 bytes, then record both digests and the scoped diff. Under package relocation, normalize only the first `package ` line and newline encoding before digest, additionally retain raw digests and assert the remaining text identical; review any discrepancies explicitly. No V1 execution/build and no whole-tree scanning of runtime files are needed. Hashes are **not measured yet**; this audit makes no claim of byte identity.

Initial, non-IPC service boundary proposed for architect review: `class IsolatedLutCatalog(private val workspace: Path, private val assetRoot: Path = workspace.resolve("backend/data/filters"))`, with `fun importCube(source: Path): ImportedLut`, `fun list(): List<ImportedLut>` and `fun load(id: String): Lut3D` (optional read-only `fun remove(id: String): Boolean` **deferred** to avoid deleting referenced assets). `ImportedLut` contains only a generated opaque ID, catalog-relative stored filename, title and parsed size, **no arbitrary absolute source path or customer image bytes**. Constructor enforces canonical V2-root containment and rejects linked components; import accepts only an explicitly selected allowed local fixture source, enforces a specified size ceiling before parsing, parses first, writes a new V2-only UUID `.cube` through temp + fsync + atomic publication, then atomically commits catalog; rollback of uncommitted new assets on failures must never overwrite an original. `load` revalidates catalog identifiers, containment, file integrity and reparses; corrupt/missing assets fail closed. Source path allowlisting, ownership and maximum size require approval before implementation. This API does **not** change IPC contracts, expose machine paths to a browser, persist effects, or run an effect on photos. Import can be implemented without touching frozen Beauty code or making a production/hardware/network call. Thus minimal source copy is technically feasible, contingent on rights verification for commercial distribution and orchestrator approval for app edits.
