## Source-backed routing and presentation delta

* V1 `Main.kt:70–76,77–125` wraps the experience in `AppShell`, displays an initialization indicator and, after an eight-second delay, a warning with Admin/skip choices. `Main.kt:125–288` maps authoritative session state to Start → Studio (layout **and** effect) → Quantity → Payment → Prepare → Capture → Select Photos → Frame → Confirm → Printing → Delivery, with Admin as a separate state. V2 `frontend/src/App.tsx:23–39` instead defaults to an English synthetic simulator and a separate architecture-proof diagnostics page; `Simulator.tsx:71–100` has the corresponding simulator state branches but uses editorial stage names and an unrelated welcome illustration. Do not treat diagnostics or synthetic previews as real camera/printing states, and do not bypass backend state to imitate V1 loading.
* V1 `AdminScreen.kt:89–141` has a 24dp-padded #FBF9F5 operator screen, back button that saves settings before exit, three status pills, and six equal 56dp tabs in this exact order: Khung / Bố cục / Cài đặt / Công cụ / Màu ảnh / Doanh thu. V2 `Operator.tsx:7–16` already uses the six tabs and embeds `V1Settings`; `v1-settings.css:2–5` uses 48px outer padding and has scroll/height constraints. Preserve tab labels/order and mounted settings draft; do not introduce a new operator workflow or claim simulated status pills represent observed devices. `App.tsx:23` exposes development-only operator/diagnostic entry and `components/StaffGestures.tsx` provides customer hidden-entry affordance; avoid replacing or exposing operator entry as customer navigation.
* V1 `SettingsTabContent.kt:42–140,170–200` implements four status cards; Windows print toggle and printer-name chips; webcam/Hot Folder choice and conditional path field/folder chooser; conditional Canon EDSDK exposure (ISO/Av/Tv/WB/picture style); three ten-second timeout steppers (0..3600); save row. V2 `V1Settings.tsx:5–15` already loads/saves precisely six backend fields, presents desired next-session settings separately from effective simulator timers, fails closed, disables unsupported folder picker/Canon operations, and registers an exit-save callback. `V1Settings.test.tsx:10–14` tests StrictMode, denial, exact payload, timer bounds and failed-exit guard. **Do not weaken these guarantees for visual parity**: backend acknowledges `NEXT_SESSION`, `PENDING_DISABLED`, all production gates false (`docs/SETTINGS_PARITY_IMPLEMENTATION.md`); settings status cards cannot honestly show Canon, print or cloud ready without actual status data. V1 restart and .env copy are explanatory only; never expose credentials in UI.
* **Tools is an actual nested tool, not a maintenance menu.** V1 `AdminScreen.kt:237–240` mounts `engine.CalculatorApp(config, layouts)` from `engine/LayoutCalculatorTool.kt:56–59`. Its two PNG entry actions measure slots or load a pre-punched frame (`:109–245,366–387`); left pane contains constrained-ratio PNG/slot/QR preview and loading/empty states (`:390–535`); right pane has print-size/layout ID, new-layout switch, frame ID, special-event name/cover, QR X/Y/size, save layout, save frame locally, generated code and Copy Code (`:538–788`). Processing writes punched PNG adjacent to input (`:158–164`); save layout uses Firebase (`:254–317`), and save frame writes local assets (`:319–359`). V2 `Operator.tsx:15–16` currently groups it as “Calculator & maintenance” and offers generic disabled cards; that phrase implies a nonexistent V1 maintenance workflow. No authorized V2 Tools import/analyze/save/clipboard/Firebase contract exists. First Tools change should be *source-accurate identification and honest unavailable entry*, not decorative calculator fields or working file upload. Backend authorization is a separate gate for actual operations.
* V1 Frames groups standard custom frames by print size → layout and special frames by event (`AdminScreen.kt:142–191`), layouts open price/count/countdown editor and guarded delete (`:194–224,418–536`). V2 operator has only simulator `operator.getStatus` and `operator.updateLayout` for counts/timing while IDLE (`Operator.tsx:9–16`, `docs/UI_BACKEND_RESULTS.md:9–10`); do not repurpose it for pricing/deletion/assets. Customer V2 `Simulator.tsx:79–97` currently has disabled unsupported camera source/import, custom frame import and delivery paths; preserve backend-owned previews, progress and simulator-only dryrun. Production parity is not implemented by these cards.
