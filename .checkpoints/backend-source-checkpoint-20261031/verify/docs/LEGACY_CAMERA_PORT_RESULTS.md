# Legacy camera port — partial, disabled and unverified

This is an incomplete source adaptation, not camera support. Hardware is not initialized, discovered, connected or controlled automatically. No hardware operations, native DLL execution, builds or tests were performed. V1 was read-only; no V1 changes, binaries, assets or secrets copied. No simulator switching or IPC changes.

## Code and provenance

`camera/legacy/LegacyCameraPort.kt` adapts the exact crop algorithm from V1 `src/main/kotlin/com/phuctran/photobooth/desktop/services/WebcamStillCaptureService.kt:54-70` (adds positive finite input validation). It ports the DroidCam-first name ordering from `:39-41` and the native constructor/open/live-view method calls from `services/NativeEosCaptureService.kt:29,38,126,150`; these use reflective class lookup only after explicit `HardwareAuthorization`. Hot Folder name snapshots/new `.jpg` detection adapt `services/HotFolderCaptureService.kt:39-53`, with deterministic ordering and no deletion. These adaptations are not a complete service or wholesale binding copy. `LegacyOriginalStore.retain` is new V2 code that stages bytes and publishes a no-overwrite hard link before a future derivative step; it does not itself process an image. `LatestLegacyPreview.publish/latest/clear` provides bounded JPEG delivery (384 KiB, 640 pixels per side); aggregate IPC snapshot limits remain the backend's responsibility.

Callable boundaries: `LegacyCanonPort(auth).open(): Boolean`, `beginLiveView(): Boolean`, `downloadLiveView(): BufferedImage?`, `close()`; `LegacyWebcamPort(auth).cameraNames(): List<String>`; `LegacyHotFolderPort(auth, workspace, input).snapshotNames()/candidates(previous)`; `LegacyOriginalStore(workspace).retain(auth, transfer, sessionDirectory, shotId): Path`. Do not activate these methods for devices: approval, ownership, resource and lifecycle controls are not complete.

## Critical blockers before integration

* No Canon shutter, autofocus, SafeShootCommand, transfer, discovery, reconnect, proper global SDK dispatcher termination, live-view stop, timeout or hang containment has been ported. `open` failure/exception cleanup and `close` during an in-flight native call require a native actor/sidecar design. The binding may perform side effects at class initialization; permission is checked before `Class.forName`. Reflective signatures and actual artifact equivalence are **not verified**. Do not enable even with the gate until the lifecycle is safe and a separately approved test plan exists.
* Webcam port has enumeration only; device selection, opening, capture and disposal are missing. Hot Folder has snapshot/candidate discovery only: stable-write/readability checks, timeout, session ownership, late-file policy and safe bounded polling are missing. Neither is ready for real input. Hot Folder requires an existing V2 directory, not a V1 or production path; path checks are not race-proof against a malicious local process.
* Original retention is byte-copy only; target extension currently assumes JPEG and cannot safely represent RAW/multiple transfers. No verified complete raw-transfer integration, legacy LUT/mirror derivative, EXIF or parity. V1 `imaging/DesktopImageProcessor.kt:19-57` effect-processes and mirrors `Photo_<index>.jpg`; V1 native deletes its temporary transfer after processing (`NativeEosCaptureService.kt:197-219`), so its processed file is not a byte-identical original.
* V1 build lists `com.bitplan:edsdk4j:0.0.1`, JNA/JNA-platform 4.5.2 and sarxos `webcam-capture:0.3.12`. A full direct port also needs V1 binding/`SafeShootCommand` dependencies, coroutines and processor/LUT dependencies or approved equivalent; dependency owner must evaluate versions and packaging. No build edits made. Wrapper loose source has a WTFPL notice in `edsdk/api/CanonCamera.java:52-56` but equivalence and all source licenses are unproven. Canon EDSDK DLL provenance, version, architecture, redistribution and license remain unverified; no SDK binaries copied. Do not ship until rights are verified.

## Isolated Hot Folder fixture implementation — follow-up

`IsolatedHotFolder(auth, workspace, input, output).beginShot(sessionId, shotId).await(timeoutMillis, pollMillis, cancelled)` is a synthetic-fixture-only API, not wired to a production profile. V1 `HotFolderCaptureService.kt:36-62` supplies the snapshot/new-JPG polling concept and 100 ms default interval; V2 adds stable size/mtime across polls, JPEG markers and ImageIO decoding, sorted candidates, cancellation and monotonic bounded timeout, content/name duplicate suppression within the adapter instance, and atomic no-overwrite full-byte original publication. Inputs are never deleted. One shot is active per instance. Session/shot identifiers label outputs; pre-existing files are excluded by each shot's baseline. A file from a previous shot arriving *after* the next shot starts cannot be distinguished from a current file: test-only writers must coordinate shot ownership. Duplicate tracking is in-memory, not restart-persistent; same-content legitimate shots are suppressed. Fixed 32 MiB compressed file limit does not bound decoded pixel dimensions. JPEG decoder acceptance is not a proof that every producer write is complete; stable metadata and EOI are heuristics. File and directory checks assume exclusive trusted local fixture writers, not malicious symlink swaps; names alone do not certify a directory is non-production. Do not use this API with real Hot Folders until ownership and filesystem race isolation are designed. No preview is exposed for this source, consistent with V1.
