## 1. Authoritative flow and exceptions

`IDLE → SELECTING → SELECTING_QUANTITY → PAYMENT_PENDING → PREPARING → LIVE_VIEW → COUNTDOWN ↔ CAPTURING → SELECTING_PHOTOS → EDITING → PRINT_PENDING → PRINTING → DELIVERY → IDLE` (M). Capture controller owns repetition, not the UI. Event bundle branches IDLE directly to quantity if its target layout exists (C323–335). Admin is entered from Welcome and readiness fallback; Admin exit resets the session (M286).

Back edges actually implemented by `goBack`: quantity→setup, payment→quantity (cancels polling), frame→photos, confirm→frame; all other cases no-op (C950–961). Studio has local back between setup steps and root back to IDLE (G; M159). Photo selection receives Back but controller does nothing: **do not invent a retake or return-to-capture route**; proposal to omit its inert Back requires parity review. No customer Back on capture, printing or delivery.

**Critical discrepancy for orchestrator/architect:** C291–311 automatically fills missing selections, chooses a first frame and calls `startPrinting(userConfirmed=false)` on inactivity. C222–255 starts timers on selection/frame and conditionally confirm. Do not reinterpret timeout as “return home” or add a “keep alive” policy. Master confirmation/revenue requirements must be reconciled against this real path by business/backend owners. UI displays backend remaining time and accurate expiry explanation; never sends a second print on expiry. C279–288 exposes timer reset, but interaction wiring requires further audit; do not reset on every touch by assumption.

**Payment discrepancy:** C388–397 does not itself verify payment; P131–145 permits cash confirmation when staff panel is visible, payment unconfigured, or QR creation errors. Preserve current gated UI wiring, flag security limitation; do not replace it with public “I paid” or claim backend authorization exists.

## 2. Shared screen contract

Every screen uses tokens/geometry in `UI_DESIGN_SYSTEM.md`: >=48px targets, >=64px primary, non-hover labels, semantic headings/status, visible focus, pending-command latch, reduced motion. Backend state is authoritative. Proposed semantic data below are **frontend needs, not existing IPC names**. At minimum expose session identity, current phase, selected layout/effect/frame, configured shot/select/countdown values, moments and selection IDs, status, remaining inactivity time, export summary, capabilities and accepted/rejected command result. ## 5. Error/recovery and frontend handoff

Errors are state decorations unless a real source route exists. Camera unavailable: inline stage message, no automatic reset or newly invented retry. Empty layouts/frames: explicit empty state and no fake sample selection. QR failure: actual staff cash gate, not a public pay bypass. Print/upload failures: render actual service result without claiming paper or QR exists. IPC disconnect is a **proposed host overlay**, not a new business state: freeze commands, retain last snapshot labeled disconnected, request an authoritative resync on reconnect; never replay side-effecting commands automatically. Architect must approve event/error/recovery capabilities before implementation.

Frontend component mapping: `WelcomeSpread`, `StudioSetup`, `QuantityPicker`, `PaymentQrPanel`, `PreparationNotice`, `PhotoStage` + `CountdownRail`, `MomentGrid`, `FrameGallery`, `PrintConfirmation`, `JobStatus`, `DeliveryPanel`, `OperatorWorkbench`. Reuse `CommandButton`, `StatusNotice`, `AspectPreview`, `TimedSelectionHeader` and `CancellationMenu` across screens. Props are canonical state, handlers are command requests, never direct printer/payment/database calls. Keep command pending/session identity outside transient animation components. Never key a fresh camera connection on countdown rerenders.

Required architect answers: allowed-transition enforcement; stale payment callbacks after Back; print/cash idempotency; auto-print timeout vs confirmation/revenue policy; selection interaction timer reset wiring; capability/readiness across camera modes; actual physical-printer status granularity; recovery commands and errors; late uploads after finish; safe image handles and stream orientation metadata. No invented event names are binding contracts.
