# Simulator camera — bounded implementation

This is a synthetic local JPEG source, not Canon, webcam or Hot Folder support. No device access, SDK initialization, native tests or physical camera tests were performed. V1 was not modified; the existing audit `05_CAMERA_AND_NATIVE_SDK_AUDIT.md` was the sole legacy reference.

## Integration API

Construct `SimulatorCamera(SimulatorAuthorization(true), workspace, sourceCount, width, height, previewWidth, previewHeight)` only after explicit operator authorization. `publishPreview(sourceIndex)` and `latestPreview()` provide a latest-only downscaled JPEG; `capture(sourceIndex, existingSessionDirectory, shotId): SimulatorCapture` serializes capture and returns source identity and the path to a full-resolution synthetic original. Source indices are zero-based and independent of session shot count and countdown. The adapter neither selects a source profile nor sequences a session or changes IPC schemas. JPEGs are generated internally; it does not accept arbitrary external photos.

Capture writes a temporary file in the target directory and atomically publishes via a hard link, failing if the original name already exists. The temporary link is deleted. The adapter never overwrites originals, but filesystem permissions do not prevent other processes modifying them. Hard-link support is required; unsupported filesystems fail rather than silently weaken atomicity. The session directory must already exist in the named V2 workspace, without symlink path components. This check is not an OS sandbox and assumes trusted local code does not concurrently replace directories. Preview arrays are defensively copied. No image processing, mirror, LUT, Beauty or production original parity is claimed.

Fixture count is explicitly limited to 1–64 as a simulator resource safety bound, not a session photo count. Only one full-resolution encoded source is retained, irrespective of source count. The latest preview is limited to 640×640 and 384 KiB JPEG (at most 512 KiB after base64, before JSON overhead). The backend must independently enforce the total 1 MiB IPC snapshot limit, including all other fields and framing; this adapter cannot guarantee it. Callers may retain their own copies, and transient image generation/decoding can use substantially more memory (up to 4096×4096 source pixels). Concurrent generation is serialized. The last successful preview remains available if a later publication fails.

The root check resolves the workspace with `toRealPath()` and requires its final directory name to be `PhotoboothDesktop_v2`. The test resolves either the V2 root or its `backend` child from the working directory; other test working directories are unsupported. The current backend production resolver instead walks upward from the code-source location looking for the exact case-sensitive V2 directory name, so it works for classes or JARs located under that named workspace, not for an independently packaged sidecar outside it. These are source-inspection observations, not an executed integration test. Renamed workspaces and relocated packaged deployments need an explicitly reviewed isolation design; the check has not been relaxed.

## Verification

Tests in `SimulatorCameraTest` exercise authorization, fixture bounds, real ImageIO decode, preview budget, latest-frame replacement, byte equality and SHA-256 after cache eviction, no overwrite and path rejection. **Not run:** concurrent Gradle is prohibited while the backend owner works; tests are ready for the coordinating agent. No latency measurements. Native init/discovery and controlled physical Canon testing remain not run and require separate authorization. Real migration is gated on simulator test success.
