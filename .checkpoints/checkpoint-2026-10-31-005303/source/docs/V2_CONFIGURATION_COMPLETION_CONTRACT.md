Source-only checkpoint (2026-10-31). V1 was inspected with read-only source tools; no `.env`, secrets, model binaries, customer assets, production runtime data, commands or hardware/network operations were accessed. **No shared IPC schema or backend application code is changed by this proposal.** File citations: V1 paths relative to `src/main/kotlin/com/phuctran/photobooth/desktop/`; V2 paths relative to `backend/src/main/kotlin/com/lesouvenir/v2/`.

## Actual baseline and precedence

- V1 `config/DesktopBoothConfig.kt:7-43` declares the runtime fields; `:45-89` loads `workingDir/.env + appDataDir/.env + System.getenv()` (later map wins: process > app-data > working), identifies a writable envSource separately, handles album URL alias and strips a trailing `/a`. `:91-125` parses comments/quotes, permissive boolean flags for print/local-server/beauty, strict booleans for camera choices, clamps album expiry to at least one day, defaults invalid timeout integers (but does not constrain valid negatives), and case-insensitively matches the Beauty preset. This precedence is a **V1 fact**, not permission to read V1 configuration in V2.
- V1 `config/SettingsManager.kt:8-39` updates six keys in `.env`, preserving other lines and appending absent keys; `controller/DesktopBoothController.kt:999-1031` updates `activeConfig` after successful save. Camera service is chosen once by `:63-68` (native > CLI > Hot Folder > webcam), so changing camera-source intentions does not hot-swap capture. V1 timeout consumption is independently per photo/frame/other state (`controller/DesktopBoothController.kt:245-269`); print permission consumption differs from restart-only source selection.
- V2 `ipc/OperatorSettingsStore.kt:9-75` is a six-field, V2-workspace JSON **nonsecret intention** store with strict validation, atomic write, and disabled production gates. `ipc/OperatorLayoutStore.kt:8-67` holds simulator-only shot/select/countdown overrides (not price or remote layout config). `ipc/SimulatorSessionEngine.kt:42,59-79,97-110,135-165,282-290` applies persisted timeout values in synthetic sessions and only reads `SIMULATOR_CAPTURE_ENABLED` and `V2_LOCAL_OPERATOR_ENABLED` for its simulator factory. `ipc/IpcMain.kt:95-101` accepts only `--simulator`. **No V2 deployment config loader currently provides the V1 runtime fields, nor are V1 `.env` or a second backend acceptable fallbacks.**

## Proposed separate deployment source (V2 only; approval required)

Introduce a backend-internal typed `DeploymentConfigLoader` and injectable `SecretProvider` with no customer/IPC access. For a packaged V2 app, select **one explicitly configured V2-owned configuration location** under V2's separate identity, not the working directory or V1 installation; in workspace-only tests use an injected fixture file under V2 `backend/build/.../PhotoboothDesktop_v2`. Deny V1 roots, links/escapes and unbounded/malformed files before parse; do not log file contents. No automatic V1 `.env` import, `.env` fallback, secrets copying, migrations, schema changes, or new database/server. Operator JSON must never override deployment identity or secret values. Proposal for precedence: compiled fail-closed defaults < explicitly selected V2 deployment fixture/config < injected per-key process environment (only allowlisted keys, if approved); secret fields come **only** from the injected secret provider and never from the operator store. Ambiguous duplicate aliases must be rejected or resolved by an explicitly tested rule. Resolve once at service startup, freeze typed snapshot per session; report nonsecret source/effective/apply status without exposing credentials. This precedence intentionally does **not** replicate V1's implicit working/app-data `.env` search; exact location/allowlist and secret provider must be chosen by architect/operator before implementation.
