# Simulator session implementation / frontend handoff

2026-10-30. V2-only implementation. Task1 real React/JVM/CDP close was independently reported passed by orchestrator; not independently repeated here. This document describes the actual narrow API, superseding inconsistent examples in the initial simulator contract. No shared/frontend files edited.

## Actual executable API

Existing 4-byte BE framing, strict UTF-8/JSON, exact five envelope keys, protocolVersion literal 1 and 1 MiB limit remain. `health.check` remains backward compatible, including its health-only availableMethods field (legacy health type requires that exact array). Session methods below are explicitly allowlisted only in simulator startup. No unsolicited stdout events: **poll session.getState**, typically 250–500ms. Responses are bounded before writing; oversize results become a redacted error.

Launch installed `backend/build/install/backend/bin/backend.bat --simulator` with Java 21 and `SIMULATOR_CAPTURE_ENABLED=true`. Without the environment opt-in, synthetic capture returns -32000; no hardware fallback. Configuration is loaded from V2 `backend/config/simulator-layouts.json`, discovered relative to the installed class location, not caller working directory.

All session requests use UUID v4 `sessionId`; all mutations also use UUID v4 `commandId` **inside params**, never top-level. Optional UUID v4 `generationId` inside params binds the session to a frontend generation: if supplied on start it must be supplied unchanged on every later request. Omission consistently uses the legacy empty generation. Supply it for stale-generation protection. New IDs after process restart are required: simulation is intentionally not a persistent financial/session recovery service.

Exact methods and additional params (beyond sessionId/generationId/commandId):

| Method | Additional params | Behavior |
|---|---|---|
| health.check | empty params, no IDs | Existing JVM health |
| catalog.get | empty params, no IDs | Full normalized LayoutMode fields, dimensions, pricing/options |
| device.getStatus | empty params, no IDs | Explicit simulator connectivity, no printer/Beauty, JVM info |
| session.start | layoutId | IDLE → SELECTING; new session directory |
| session.getState | no commandId | Poll authoritative snapshot |
| session.setLayout | layoutId | Only SELECTING |
| session.confirmSetup | none | SELECTING → SELECTING_QUANTITY |
| session.setQuantity | integer quantity 2..50 | Source sanitizer; advances PAYMENT_PENDING |
| payment.mockComplete | none | PAYMENT_PENDING → PREPARING → LIVE_VIEW after 1600ms; no payment/revenue |
| capture.startSequence | none | LIVE_VIEW, paid and opt-in required; async configured countdown/shots |
| selection.toggle | zero-based shotIndex | Only SELECTING_PHOTOS, capped selectCount |
| selection.confirm | none | Exact selectCount → EDITING |
| frame.list | no commandId | Only EDITING; generated synthetic frame thumbnail |
| frame.select | frameId="synthetic-border" | Actual compositor outputs; stays EDITING |
| frame.confirm | none | Requires chosen frame; PRINT_PENDING |
| print.confirmDryRun | none | PRINT_PENDING → DELIVERY, userConfirmed=true, accepted=false, revenue=false |
| session.back | none | Source edges: SELECTING→IDLE, SELECTING_QUANTITY→SELECTING, PAYMENT_PENDING→SELECTING_QUANTITY, EDITING→SELECTING_PHOTOS, PRINT_PENDING→EDITING |
| session.cancel | none | Only SELECTING_PHOTOS/EDITING → IDLE |
| session.finish | none | **Only DELIVERY** → IDLE |

`session.transition`, `capture.abort`, arbitrary reset, real print and all unknown methods return -32601. No FINISHED state. SELECTING_PHOTOS→quantity Back is intentionally forbidden: it is not a source-derived edge. Both selection/editing inactivity use source-derived auto-fill/first frame/render flow to DELIVERY with **userConfirmed=false**, no print acceptance or revenue. Timer defaults 30s from config, resets on successful user mutations, not polling.

Mutations generally return full snapshot plus commandId. payment.mockComplete returns `{paid:true,commandId}`; capture.startSequence returns `{shotIndex:1,totalShots,countdownSeconds,commandId}`; cancel returns `{cancelled:true,state:"IDLE",commandId}`; frame.list returns `{frames:[{id,name,thumbDataUrl}]}`. Dryrun returns snapshot plus compositionDataUrl and printImageDataUrl.

Snapshot includes sessionId, generationId, state, layout, pricing, quantity, paid, capturedCount, selectedCount, selectedIndices, shotIndex, secondsRemaining, totalShots, shots:[{shotIndex,shotId,preview}], frameId, previewDataUrl, compositionDataUrl, printImageDataUrl, livePreviewDataUrl, userConfirmed, printAccepted:false, revenueRecorded:false, simulator:true, failure. Nullable images remain null until complete. Live JPEG is generated by actual SimulatorCamera.publishPreview in LIVE_VIEW/COUNTDOWN. Composition/print JPEG previews are scaled from actual full-resolution files and remain available in queried state through DELIVERY. No filesystem paths exposed.

Example envelopes (use fresh UUIDs per actual session/command):

```json
{"jsonrpc":"2.0","id":"start","method":"session.start","params":{"sessionId":"11111111-1111-4111-8111-111111111111","generationId":"22222222-2222-4222-8222-222222222222","commandId":"33333333-3333-4333-8333-333333333333","layoutId":"strip-2"},"protocolVersion":1}
{"jsonrpc":"2.0","id":"setup","method":"session.confirmSetup","params":{"sessionId":"11111111-1111-4111-8111-111111111111","generationId":"22222222-2222-4222-8222-222222222222","commandId":"44444444-4444-4444-8444-444444444444"},"protocolVersion":1}
{"jsonrpc":"2.0","id":"poll","method":"session.getState","params":{"sessionId":"11111111-1111-4111-8111-111111111111","generationId":"22222222-2222-4222-8222-222222222222"},"protocolVersion":1}
```

Duplicate `(sessionId,commandId)` with same serialized method/params returns stored response without effects; reuse with different request fails -32602. Different command ID repeated dryrun is rejected after DELIVERY. Session IDs cannot be reused; async epoch/session guards prevent callbacks after reset/close. Dedup is bounded to 2048 mutations per process (then locked); restart requires new session IDs. It is not 24h durable production reconciliation. Cancellation retains synthetic files for test evidence; no customer files or real revenue ever exist in this adapter.

## Assets / source parity

Existing foundation unchanged; uses specialist-owned SimulatorCamera and SimulatorCompositor APIs without edits to those subtrees. Config fixtures intentionally differ: strip-2 = 3 shots / select 2 / 1s; grid-4 = 5 / 4 / 2s. These are **synthetic test choices, not real bundles**. Model fields/pricing algorithm are attributed to existing V1-derived foundation. Optional supplied LayoutMode config fields override defaults. Generated transparent RGBA border PNG is a V2 synthetic test asset saved per session; center is transparent. Originals are camera-written JPEGs, never overwritten; compositor consumes those files and overlay. Actual composition/print PNG files reside under backend/build/simulator-sessions/<sessionId>.
