# File-only print simulator

`com.lesouvenir.v2.printing.SimulatorCompositor.generate` accepts a V2 `LayoutMode`, already processed `BufferedImage` photos, and a custom transparent frame image. It writes a composition and print-paper PNG or JPEG and returns `FILE_GENERATED`, not a print success. Caller supplies distinct V2-owned output paths and is responsible for authorization, session isolation, input validation and preview display. No printer, spooler, cut command or hardware access is performed.

Source attribution: V1 `desktop/imaging/DesktopCompositor.kt`, `renderFinal` custom-frame rendering and paper canvas branches (lines 29–187), `computeSlots` (197–233), `configure` (235–240), `drawCenterCrop` (242–266), `drawCustomOverlay` (268–271). Includes 2x canvas dimensions, white background, four-pixel total bleed, bicubic crop, alpha frame last and two strips on one portrait paper canvas. Label classification intentionally matches V1. Strip pairing does not establish any physical cut setting. JPEG uses ImageIO defaults; PNG is the V1 output format.

Scope is deliberately bounded: custom frame branch only; no default frame drawing, QR, LUT/beauty processing, driver scaling, DPI metadata, queue, printer discovery, idempotency, or actual print. Supply already processed photos and an already loaded PNG frame; do not treat this as full V1 parity. V1 `PhotoCompositor.renderComposition` is a different algorithm and is not substituted here. No driver/SDK license was evaluated. Synthetic tests cover dimensions, frame alpha, crop, paired strip placement and file generation; V1-vs-V2 golden comparisons, full preview parity and hardware verification remain outstanding. Tests were written but not run here to avoid concurrent Gradle execution.
