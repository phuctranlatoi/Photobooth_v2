## Preserved behavior / positive findings

- Actual desktop invoke is used; browser mode throws rather than fabricating a backend (`Simulator.tsx:5–7`). Phase normally comes from `session.getState`, not a React countdown or optimistic next-step assignment (20–26, 47, 51).
- Explicit “Simulate payment approval” and dryrun/no-revenue labels are present (54, 60, 66–67). Counts and selection requirement come from snapshot/configuration (57, 62–63); no retake or capture cancel is exposed.
- A shared command lock blocks concurrent button requests (40–41); primary controls inherit ≥64px height. Images use contain; cancellation requires a second confirmation and defaults focus to continuing. These are useful foundations, not proof of backend idempotency or full touch acceptance.
- FINISHED is now a declared simulator terminal state in shared types (141, 156); rendering it is not itself an invented production delivery stage. Its success/result semantics still require Task 2 verification.
